# ตั้งค่ามือถือ Android ให้ส่งการแจ้งเตือน TrueMoney เข้า wallet-watch (25 พ.ย. 2569)

ใช้กับมือถือที่ล็อกอิน TrueMoney Wallet อยู่แล้ว เครื่องละ 1 วอเล็ต · ใช้เวลาเครื่องละ ~10 นาที · ต้องเป็น Android (iPhone ส่งต่อการแจ้งเตือนไม่ได้)

## ก่อนเริ่ม (คนดูแลระบบทำ)
1. เปิด https://wallet.yoalink.com (มีรหัสเข้า) → เมนู **Wallet** → การ์ด "เพิ่ม Wallet" → กรอก ชื่อเรียก (เช่น SM-01) · เบอร์ 4 ตัวท้าย · แบรนด์ · ผู้ถือ · วงเงินรับ/วัน → **เพิ่ม**
2. ระบบแสดง URL แบบ `https://wallet.yoalink.com/hook/XXXXXXXX` **ครั้งเดียว** (ฐานข้อมูลเก็บแค่ hash ดูย้อนหลังไม่ได้) คัดลอกส่งให้คนถือเครื่องนั้น (ส่งทางช่องทางส่วนตัว ห้ามโพสต์ในกลุ่ม) · ถ้าหาย กดปุ่ม "token ใหม่" ในแถวของวอเล็ตนั้น

## เลือกแอปบนมือถือ (26 พ.ย. 2569)

- **แอปส่งต่อ SMS ไป URL ไม่มีใน Play Store** เพราะนโยบาย Google Play ไม่ให้แอปอ่าน SMS แล้วส่งออกไปที่อื่น (Play Protect มองเหมือนมัลแวร์ขโมย SMS) SmsForwarder ของ pppscn จึงแจกเป็น APK บน GitHub/F-Droid เท่านั้น
- **ถ้าเอาแค่จาก Play Store ใช้ MacroDroid** (แอป automation ชื่อดัง ฟรี 5 มาโคร พอใช้) ส่งต่อ "การแจ้งเตือนของแอป TrueMoney" ได้ ซึ่งพอสำหรับงานนี้ เพราะ TrueMoney แจ้งเตือนในแอปทุกรายการเงินเข้า–ออกอยู่แล้ว ไม่จำเป็นต้องใช้ SMS
- SmsForwarder (APK) ยังเป็นตัวที่ครบกว่า (มีทั้ง SMS และ notification · ส่งซ้ำเมื่อเน็ตหลุด) ถ้าคนถือเครื่องติดตั้ง APK เองได้ให้ใช้ตัวนี้

## ทางที่ 1 (Play Store): MacroDroid
1. ติดตั้ง **MacroDroid** จาก Play Store → เปิดแอป → ให้สิทธิ์ที่ถาม · ไปที่ Settings ของเครื่อง → แบตเตอรี่ → MacroDroid → ไม่จำกัด · เปิด Autostart ถ้าเครื่องมี
2. **Add Macro** ตั้งชื่อ `TrueMoney → wallet-watch`
3. **Trigger** → Notification → **Notification Received** → เลือก Select Application(s) → ติ๊ก **TrueMoney Wallet** → เนื้อหา "Any" → ตกลง (ระบบจะพาไปเปิด Notification access ให้ MacroDroid ถ้ายังไม่เปิด)
4. **Action** → Connectivity → **HTTP Request**
   - Method **POST** · URL `https://wallet.yoalink.com/hook/XXXXXXXX` (ของเครื่องนั้น)
   - Content type `application/json`
   - Body เลือก "Text" แล้ววาง
     ```
     {"from":"{not_app_name}","title":"{not_title}","text":"{not_text}","timestamp":"{year}-{month_digit}-{dayofmonth}T{hour}:{minute}:{second}+07:00"}
     ```
     (ตัวแปรในปีกกาคือ Magic Text ของ MacroDroid กดปุ่ม "..." ข้างช่องแล้วเลือกได้ ไม่ต้องพิมพ์เอง)
5. Constraint ไม่ต้องใส่ → บันทึกมาโคร → กด "Test actions" ครั้งหนึ่งเพื่อดูว่าระบบตอบ `{"ok":true}` (ข้อความทดสอบจะไปอยู่ในเมนู Exception ว่า "ข้อความแยกไม่ออก")
6. ถ้าอยากได้ SMS ด้วย: Trigger → **SMS Received** (ผู้ส่งมีคำว่า TrueMoney) แล้วใช้ Body `{"from":"{sms_name}","text":"{sms_message}"}` · MacroDroid เวอร์ชัน Play อาจขอให้ติดตั้งตัวช่วย (Helper) สำหรับสิทธิ์ SMS ทำตามที่แอปบอก หรือข้ามข้อนี้ไปเลยก็ได้

## ทางที่ 2 (APK): SmsForwarder
แอปโอเพนซอร์ส ส่งต่อทั้ง SMS และการแจ้งเตือนของแอปอื่นไป webhook ได้ ไม่ต้องรูท
1. ดาวน์โหลด APK จากมือถือโดยตรง (หน้า GitHub เป็นภาษาจีน ไม่ต้องอ่าน ใช้ลิงก์ตรงนี้ได้เลย · รุ่นล่าสุด v3.5.0 ออก 14 ก.พ. 2569):
   - ลิงก์ตรง: https://github.com/pppscn/SmsForwarder/releases/download/v3.5.0/SmsF_3.5.0.260224_100055_universal_release.apk (ไฟล์ universal 19 MB ใช้ได้ทุกเครื่อง)
   - หรือเปิด https://github.com/pppscn/SmsForwarder/releases/latest เลื่อนลงล่างสุดถึงหัวข้อ **Assets** แล้วกดไฟล์ที่ลงท้าย `_universal_release.apk`
   - ติดตั้ง (เครื่องจะถามให้อนุญาต "ติดตั้งจากแหล่งที่ไม่รู้จัก" ให้ Chrome/ตัวจัดการไฟล์ชั่วคราว) · ถ้า Play Protect เตือน กด "ติดตั้งต่อไป" (เตือนเพราะเป็นแอปอ่าน SMS ตามที่อธิบายข้างบน)
   - เปิดแอปครั้งแรกจะขึ้นกล่อง **温馨提示** (ข้อตกลงความเป็นส่วนตัว) → กด **同意** (ปุ่มขวา = ยอมรับ · กด 不同意 แล้วใช้แอปไม่ได้) → เครื่องถามสิทธิ์แจ้งเตือน → อนุญาต
     ตรวจซอร์สแล้ว (26 พ.ย. 2569): การยอมรับคือเปิดใช้ Umeng (SDK สถิติของจีน) ซึ่งส่งรหัสเครื่อง รุ่นเครื่อง และหน้าที่เปิดในแอปไปที่ Umeng
     ส่วนเนื้อข้อความส่งไปที่ Webhook ที่เราตั้งเท่านั้น · ถ้าไม่อยากมี SDK จีนบนมือถือวอเล็ต ให้ใช้ MacroDroid (ทางที่ 1) แทน
   - เปลี่ยนเป็นภาษาอังกฤษ: **通用设置** (General settings) → **多语言设置** → English → ปิดแล้วเปิดแอปใหม่ (ไม่มีภาษาไทย)
   - ชื่อเมนูภาษาจีน: 通用设置·第一步 = ตั้งค่า · 发送通道·第二步 = Sender · 转发规则·第三步 = Rule · 转发日志·第四步 = Log
2. เปิดแอป → ให้สิทธิ์ตามที่ถาม: อ่าน SMS · การแจ้งเตือน · โทรศัพท์ · ทำงานเบื้องหลัง
3. **สำคัญที่สุด** ตั้งให้แอปไม่ถูกฆ่า: Settings ของเครื่อง → แบตเตอรี่ → SmsForwarder → "ไม่จำกัด / ไม่ประหยัดพลังงาน" · เปิด "เริ่มอัตโนมัติ (Autostart)" ถ้าเครื่องมี (Xiaomi/Oppo/Vivo/Realme มี) · ล็อกแอปไว้ใน Recent apps
4. ในแอป SmsForwarder → **通用设置 / Settings** → เปิด **转发应用通知 / Forward App Notifications** (ให้สิทธิ์ Notification access ก่อน) · ยังไม่ต้องเปิด 转发短信广播 / Forward SMS
   - Android 13 ขึ้นไป (เช่น Samsung): หน้า Notification access จะขึ้นว่า "ควบคุมโดยการตั้งค่าที่จำกัด" กดสวิตช์ไม่ได้ เพราะแอปติดตั้งจาก APK
     → ตั้งค่าเครื่อง → แอปพลิเคชัน → 短信转发器 → ⋮ มุมขวาบน → "อนุญาตการตั้งค่าที่จำกัด" → ยืนยันรหัสเครื่อง แล้วกลับมาเปิดสวิตช์
     · ประเภทการแจ้งเตือน 4 ช่อง (เรียลไทม์ · การสนทนา · การแจ้งเตือน · ปิดเสียง) เปิดไว้ทั้งหมด เพราะไม่รู้ว่า TrueMoney ถูกจัดอยู่ประเภทไหน
   - เปิด **忽略电池优化设置** (ไม่ประหยัดแบต) และ **开机启动** (เปิดเองตอนเปิดเครื่อง)
   - แนะนำเปิด **自动消除通知** (ลบการแจ้งเตือนทิ้งหลังส่งต่อแล้ว) ใส่ `th.co.truemoney.wallet` · Android โชว์การแจ้งเตือนค้างได้ราว 50 อันต่อแอป วอเล็ตที่รับวันละหลายร้อยรายการ ถ้าไม่มีใครเคลียร์ อันใหม่อาจไม่ขึ้นและจะหายเงียบ · ผลข้างเคียง: คนถือเครื่องจะไม่เห็นการแจ้งเตือน TrueMoney ค้างในแถบแจ้งเตือน

## ตั้งช่องทางส่ง (Sender) เป็น Webhook
แท็บ **Sender** → **+** → เลือก **Webhook**
- ชื่อ: `wallet-watch`
- Method: **POST**
- Webserver (URL): วาง URL ที่ได้จากข้อก่อนเริ่ม เช่น `https://wallet.yoalink.com/hook/XXXXXXXX`
- Web params / Body (JSON): วางตามนี้ทั้งก้อน
  ```
  {"from":"[from]","title":"[title]","text":"[org_content]","timestamp":"[receive_time]"}
  ```
  ตรวจกับซอร์ส SmsForwarder v3.5.0 (`WebhookUtils.kt`, `MsgInfo.kt`) เมื่อ 26 พ.ย. 2569:
  - `[from]` = ชื่อแพ็กเกจแอป (`th.co.truemoney.wallet`) ถ้าเป็นการแจ้งเตือน · เบอร์/ชื่อผู้ส่งถ้าเป็น SMS
  - `[title]` = หัวข้อการแจ้งเตือน · ถ้าเป็น SMS แอปจะใส่ `SIM1_<หมายเหตุซิม>` แทน
  - `[org_content]` = เนื้อความดิบ · **ห้ามใช้ `[msg]`/`[content]`** เพราะเป็นข้อความที่แอปจัดรูปแล้ว มีชื่อแพ็กเกจ ช่องซิม UID เวลา และชื่อเครื่องปนมาหลายบรรทัด
  - `[receive_time]` = เวลาที่มือถือได้รับ รูปแบบ `yyyy-MM-dd HH:mm:ss` ตามนาฬิกาเครื่อง ไม่มีโซนเวลา (เซิร์ฟเวอร์ตั้งเป็น Asia/Bangkok จึงอ่านเป็นเวลาไทยถูก)
  - `[device_name]` ไม่มีในแอป ส่งไปจะได้คำนี้ตรงตัว จึงไม่ใส่
- Headers: `Content-Type: application/json`
- กด **ทดสอบ (Test)** → ถ้าตั้งถูก ระบบตอบ `{"ok":true,...}` และหน้า Dashboard จะเห็นวอเล็ตนี้ "ส่งล่าสุด เมื่อกี้" (ข้อความทดสอบจะไปอยู่ในเมนู Exception ว่า "ข้อความแยกไม่ออก" ไม่เป็นไร) · ถ้าตอบ `token ไม่ถูกต้อง` = URL ผิดหรือ token ถูกออกใหม่แล้ว
  · ถ้าขึ้น **Request failed: HTTP 400** = URL ขึ้นต้นด้วย `http://` หรือไม่มี `https://` → Cloudflare เด้งไป https ด้วย 301 แล้วแอปตามไปแบบ GET ไม่มีเนื้อข้อความ (เจอจริง 26 พ.ย. 2569) แก้ให้ขึ้นต้นด้วย `https://` · Proxy ไม่ต้องตั้ง (None)
- บันทึก

## ตั้งกติกาส่งต่อ (Rule)
แท็บ **Rule** → **+**
1. **App notification (ต้องทำ)**: ประเภท App · เงื่อนไข "แพ็กเกจ/ชื่อแอป" = TrueMoney Wallet (`th.co.truemoney.wallet`) · Sender = wallet-watch · บันทึก
2. **SMS (ทางเลือก ยังไม่ต้องทำในเครื่องแรก)**: ประเภท SMS · เงื่อนไข "ผู้ส่ง มีคำว่า" `TrueMoney` · Sender = wallet-watch · ห้ามเลือก "ทั้งหมด" เพราะจะส่ง OTP ของแอปอื่นมาด้วย · **ปล่อยช่องหมายเหตุซิม (SIM1/SIM2 remark) ในตั้งค่าแอปให้ว่าง** เพราะแอปเอาค่านี้ใส่ใน `[title]` ถ้ามีเบอร์เต็มจะหลุดเข้าระบบ (ระบบเก็บเบอร์ได้แค่ 4 ตัวท้าย)

## ทดสอบของจริง
1. ออกจากแอป TrueMoney ไปหน้าโฮม (ถ้าเปิดแอปค้างไว้ แอปอาจไม่ขึ้นการแจ้งเตือน แล้ว SmsForwarder จะไม่เห็น) · แล้วให้คนอื่นโอนเข้าวอเล็ตนี้ 1 บาท
2. ภายใน 1 นาที หน้า https://wallet.yoalink.com เมนู Dashboard ต้องเห็น "รับวันนี้" ขยับและ "เงินเข้าล่าสุด เมื่อกี้" (คนดูแลระบบตรวจ: Transaction หรือ log ของ nginx `/var/log/nginx/wallet.access.log` · `journalctl -u wallet-watch` ไม่แสดงคำขอที่เข้ามา มีแค่ตอนเริ่มและตอนผิดพลาด)
3. ถ้าขึ้นในเมนู **Exception** ว่า "ข้อความแยกไม่ออก" แทน → ก๊อปข้อความนั้นมาเพิ่มกติกาใน `lib/parse.mjs` แล้วจะนับย้อนหลังให้
4. ทดสอบเงินออก 1 บาท: โอนจากในแอป แล้วกลับไปหน้าโฮม รอ 1 นาที ดูว่ามีการแจ้งเตือนเงินออกขึ้นที่แถบแจ้งเตือนไหม (บางแอปไม่แจ้งเตือนรายการที่ทำเองในแอป)

## API กลาง: ให้ TrueMoney ส่งมาที่เรา แล้วเราส่งต่อให้ผู้ให้บริการ (26 พ.ย. 2569)
> **พักใช้ตั้งแต่ 26 พ.ย. 2569 23:15** ลองกับวอเล็ตที่ผูก t-wallet แล้ว ผู้ให้บริการตอบ 200 ทุกครั้ง แต่ไม่เติมเครดิตเข้ายูสลูกค้าเลย จึงถอยกลับมาจับผ่าน SmsForwarder อย่างเดียว
> ห้ามย้ายวอเล็ตใดตามขั้นตอนนี้ จนกว่าผู้ให้บริการจะยืนยันว่ารองรับการรับข้อมูลผ่านเรา
ใช้กับวอเล็ตที่ตั้ง Webhook API ไว้แล้ว (เช่น ผูกระบบฝากออโต้ของผู้ให้บริการ) · ได้เฉพาะเงินเข้า/เติมเงิน (TrueMoney ไม่ส่งเงินออก ทั้งทาง API และการแจ้งเตือน)
ระบบเราส่งต่อข้อมูลให้ผู้ให้บริการทุกไบต์ก่อนทำอย่างอื่น และตอบ TrueMoney ตามผลของผู้ให้บริการ ถ้าผู้ให้บริการไม่รับ TrueMoney จะส่งซ้ำเอง (1 · 5 · 15 นาที)

**ย้ายทีละใบ ช่วงคนฝากน้อย มีคนเฝ้า 2 คน (คนถือมือถือ + คนดูหน้าเว็บ)**
1. **ก่อนเปลี่ยน** ถ่ายภาพหน้าตั้งค่า API ในแอปเก็บไว้: Endpoint URL เดิมของผู้ให้บริการ · secret ที่ปิดไว้ (เช่น `39***2f`) · สวิตช์รับเงิน/เติมเงิน
2. **หน้า Wallet ของเรา (ทำก่อนข้อ 3 เสมอ)** → แก้ → ช่อง "ส่งต่อไปปลายทางเดิม" ใส่ URL เดิมของผู้ให้บริการให้ตรงทุกตัวอักษร → บันทึก
3. **แอป TrueMoney** → ยกเลิก/เปลี่ยนการรับ API → Endpoint URL = `https://wallet.yoalink.com/tm/XXXXXXXX` (token ของวอเล็ตนั้น) · สวิตช์รับเงิน/เติมเงินเปิดเหมือนเดิม → บันทึก
   ถ้าแอปโชว์ Webhook Secret Key ให้คัดลอกใส่หน้า Wallet ช่อง "TrueMoney Webhook Secret" (ส่งทางแชทส่วนตัวเท่านั้น) · จดว่าเลขที่ปิดไว้เปลี่ยนจากเดิมไหม
4. **โอนเข้า 1 บาท แล้วเช็ก 4 จุด**
   - แอป TrueMoney "สถานะรายการที่ส่งไปล่าสุด" = http 200
   - หน้า Wallet ของเรา "ส่งต่อ → … ล่าสุด 200"
   - **หลังบ้านผู้ให้บริการเติมเครดิตเข้ายูสจริง (ข้อนี้สำคัญที่สุด ผู้ให้บริการตอบ 200 ไม่ได้แปลว่าเติมแล้ว)**
   - หน้า Transaction ของเรามีรายการ 1 บาท
5. **ข้อไหนไม่ผ่าน** → แอป TrueMoney ใส่ URL เดิมของผู้ให้บริการกลับทันที (จากภาพข้อ 1)
   รายการที่ผู้ให้บริการตอบไม่ผ่าน TrueMoney จะส่งซ้ำเอง · แต่รายการที่ผู้ให้บริการตอบ 200 ไปแล้วแต่ไม่เติมเครดิต TrueMoney **ไม่ส่งซ้ำ** แบรนด์ต้องเติมมือ (ดูรายการจากหน้า Transaction ช่วงเวลาที่ย้าย)

ข้อควรระวังหลังย้าย
- ห้ามกด "token ใหม่" ของวอเล็ตที่ส่งต่ออยู่ (URL ในแอปจะใช้ไม่ได้ทันที ฝากออโต้หยุด) ระบบจะถามยืนยันพิเศษ
- ห้ามล้างช่อง "ส่งต่อไปปลายทางเดิม" ขณะที่แอปยังชี้มาที่เรา
- ทุก 4 เดือนต้องเข้าแอปไปกด "ต่ออายุ" URL ไม่งั้น TrueMoney หยุดส่ง
- ส่งต่อไม่สำเร็จ = ขึ้นการเตือน "ส่งต่อผู้ให้บริการไม่สำเร็จ" (ตั้ง Telegram ไว้จะเด้งเข้ากลุ่ม)
- restart/deploy ระบบเรา = ฝากออโต้ช้าไปราว 1 นาที (TrueMoney ส่งซ้ำ) ควร deploy ช่วงคนฝากน้อย

## ข้อห้ามและข้อควรระวัง
- ห้ามส่งต่อ SMS ที่เป็น OTP ออกไปที่อื่น นอกจาก webhook ของระบบนี้ (ระบบเก็บไว้ในช่อง "แยกไม่ออก" และไม่ใช้ทำอะไร แนะนำตั้งกติกา SMS ให้กรองเฉพาะผู้ส่ง TrueMoney จะได้ไม่ส่ง OTP ของแอปอื่นมา)
- URL ที่มี token = กุญแจของเครื่องนั้น ถ้าหลุดให้กด "ออก token ใหม่" แล้วตั้งในแอปใหม่
- มือถือต้องต่อเน็ตและเปิดตลอด ถ้าเครื่องเงียบเกิน 30 นาทีช่วง 08:00–02:00 ระบบจะเตือน "ข้อมูลขาด"
- เปลี่ยนเครื่อง/ล้างเครื่อง = ทำใหม่ตั้งแต่ติดตั้งแอป และออก token ใหม่
